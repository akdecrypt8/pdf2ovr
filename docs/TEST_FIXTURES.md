# Test fixture design and evidence limits

## Included synthetic files

The test suite includes two small, deterministic binary fixtures:

- `tests/fixtures/synthetic_classic.ovr`
- `tests/fixtures/synthetic_modern.ovr`

They are generated by `tests/fixtures/build_synthetic_ovr.py`. The generator
constructs the EHFA header indirection, `Ehfa_File` structure, fixed-size entry
headers, absolute entry/data pointers, parent/child/sibling relationships and
an embedded compact HFA dictionary. Typed payloads are encoded through the
same public HFA dictionary codec used by the writer, then the fixtures are
checked using both the package's HFA reader and a separate test-side structural
walk using Python's `struct` module.

The checked-in fixture bytes are compared against freshly generated bytes in
the test suite, so accidental edits or stale binaries fail CI.

## Coverage

### `synthetic_classic.ovr`

A compact classic annotation tree containing:

- an `EHFA_HEADER_TAG` and indirect `Ehfa_File` header;
- a root entry and an `ElementList` node;
- an `Element_Eant` parent with the observed `EANT_ELLIPSE` enum;
- an `Eant_Ellipse` typed geometry child;
- coordinate-unit records, polynomial transform records, and a 2-row by
  4-column f64 parent `bBox` block.

### `synthetic_modern.ovr`

A compact modern annotation tree containing:

- the same HFA container/header and entry-tree primitives;
- `Element_2_Eant` parent records;
- `Text2` with a `TextBox_Eant` child;
- `Rectangle2` geometry;
- a group metadata record with a `Legend4` child;
- a nested `Polyline2` / `VectorData_2_Eant` coordinate record;
- coordinate-unit records, polynomial transforms, and parent `bBox` blocks.

The modern fixture exercises both top-level and nested annotation traversal.
The writer tests use these records as templates to test clone and creation
paths, then re-open the output and decode the typed payloads.

## Verified facts versus synthetic assumptions

The binary envelope choices used by the fixtures (header pointer at offset 16,
`Ehfa_File` structure, 128-byte entry headers seen in the examined examples,
entry-tree pointer relationships and compact dictionary syntax) are grounded in
the local reference examples and the public GDAL HFA implementation. The
EANT parent/child names, enum labels and selected fields are based on the
observed `Element_Eant` / `Element_2_Eant` examples.

The fixture files are nevertheless **synthetic parser/writer regression data**.
They are not complete ERDAS IMAGINE exports, are not independently opened by
ERDAS, and do not prove that every default value, optional field, style
reference, group semantic, data-block arrangement or version-specific detail
matches the application. The compact embedded dictionary intentionally
contains only the definitions needed for the cases listed above. It is not a
complete EANT dictionary or a universal OVR template.

The independent structural walk checks the raw header, entry tree, offsets,
string fields, pointer relationships and ranges without calling `HFAReader`.
The typed EANT decode tests exercise the production dictionary parser and
reader. This separation catches many structural regressions, but the typed
fixture encoder and decoder share the HFA dictionary implementation; it is
not an independent third-party implementation of the full format.

## External reference files

Two OVR examples were provided during development: `colorscale.ovr` and
`lnlandc.map.ovr`. They informed the schema observations documented in
[EHFA_EANT_FORMAT.md](EHFA_EANT_FORMAT.md) and
[EANT_WRITER.md](EANT_WRITER.md). They are **not included** in this repository
because redistribution rights have not been established. The automated test
suite does not require them and does not skip core parser/writer tests when
they are absent.

Developers who have lawful local copies may inspect them manually:

```bash
pdf2ovr inspect /path/to/colorscale.ovr --json
pdf2ovr inspect /path/to/lnlandc.map.ovr --json
```

## Malformed-input coverage

The HFA reader tests include truncated headers, invalid header/root/dictionary
pointers, out-of-bounds or overlapping data, broken tree relationships, cycle
and nesting-limit cases, and invalid safety limits. Additional dictionary and
EANT tests validate malformed types, missing child records and typed-payload
errors. Synthetic fixtures are deterministic and checked in; the generator is
run only when intentionally rebuilding those binaries.
